## 🚀 3716. Find Churn Risk Customers

### 📖 Problem

Write a solution to Find **Churn Risk Customers** - users who show warning signs before churning. A user is considered **churn risk customer** if they meet ALL the following criteria:

- Currently have an **active subscription** (their last event is not cancel).
- Have performed **at least one** downgrade in their subscription history.
- Their **current plan revenue** is less than `50%` of their historical maximum plan revenue.
- Have been a subscriber for **at least** `60` days.

Return the result table ordered by `days_as_subscriber` in ***descending*** order, then by `user_id` in ***ascending*** order.

Note: days_as_subscriber is calculated from the first event date to the last event date for each user.

### 💡 Idea

The goal is to identify **churn risk customers**.

A customer qualifies if they:

- Currently have an **active subscription** (their latest event is **not** `cancel`).
- Have performed at least **one downgrade**.
- Their current monthly revenue is **less than 50%** of their historical maximum monthly revenue.
- Have been a subscriber for at least **60 days**.

We first determine each user's latest subscription status and calculate their subscription statistics using CTEs, then filter users who satisfy all the conditions.

---

### 💻 MySQL Solution

```sql
WITH latest_event AS (
    SELECT *,
    ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY event_date DESC) AS rn
    FROM subscription_events),
stats AS (
    SELECT user_id,
    MIN(event_date) AS first_subscription_date,
    MAX(monthly_amount) AS max_historical_amount,
    SUM(event_type = 'downgrade') AS downgrade_count
    FROM subscription_events
    GROUP BY user_id)
SELECT l.user_id, l.plan_name AS current_plan, l.monthly_amount AS current_monthly_amount,
s.max_historical_amount,
DATEDIFF(l.event_date, s.first_subscription_date) AS days_as_subscriber
FROM latest_event l
JOIN stats s ON l.user_id = s.user_id
WHERE
    l.rn = 1
    AND l.event_type != 'cancel'
    AND s.downgrade_count >= 1
    AND l.monthly_amount / s.max_historical_amount < 0.5
    AND DATEDIFF(l.event_date, s.first_subscription_date) >= 60
ORDER BY days_as_subscriber DESC, l.user_id ASC;
```

---

### 🛠️ How It Works

1. The `latest_event` CTE uses `ROW_NUMBER()` to identify each user's latest subscription event.
2. The `stats` CTE calculates:
   - First subscription date.
   - Highest monthly subscription amount.
   - Number of downgrade events.
3. Join both CTEs using `user_id`.
4. Keep only users whose:
   - Latest event is **not** `cancel`.
   - Have at least one downgrade.
   - Current monthly amount is less than **50%** of their historical maximum.
   - Subscription duration is at least **60 days**.
5. Sort the result by subscriber duration (descending) and user ID (ascending).

---

### ⏱️ Complexity

**Time Complexity:** `O(n log n)`

- The window function sorts each user's events, while the aggregation scans the table once.

**Space Complexity:** `O(n)`

- Used to store the intermediate CTE results.
