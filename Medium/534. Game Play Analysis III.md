## 🚀 534. Game Play Analysis III 🔒

### 📖 Problem

Write a solution to report for each player and date, how many games played **so far** by the player. That is, the total number of games played by the player until that date. Check the example for clarity.

Return the result table in **any order**.

---

### 📝 Example

```text
Input: 
Activity table:
+-----------+-----------+------------+--------------+
| player_id | device_id | event_date | games_played |
+-----------+-----------+------------+--------------+
| 1         | 2         | 2016-03-01 | 5            |
| 1         | 2         | 2016-05-02 | 6            |
| 1         | 3         | 2017-06-25 | 1            |
| 3         | 1         | 2016-03-02 | 0            |
| 3         | 4         | 2018-07-03 | 5            |
+-----------+-----------+------------+--------------+
Output: 
+-----------+------------+---------------------+
| player_id | event_date | games_played_so_far |
+-----------+------------+---------------------+
| 1         | 2016-03-01 | 5                   |
| 1         | 2016-05-02 | 11                  |
| 1         | 2017-06-25 | 12                  |
| 3         | 2016-03-02 | 0                   |
| 3         | 2018-07-03 | 5                   |
+-----------+------------+---------------------+
Explanation: 
For the player with id 1, 5 + 6 = 11 games played by 2016-05-02, and 5 + 6 + 1 = 12 games played by 2017-06-25.
For the player with id 3, 0 + 5 = 5 games played by 2018-07-03.
Note that for each player we only care about the days when the player logged in.
```

---

### 💡 Idea

The goal is to calculate the **cumulative number of games played** by each player up to every login date.

For every player:

- Sort their records by `event_date`.
- Keep adding `games_played` from the first login up to the current login.

---

### 💻 Approach 1: Window Function (`SUM`) *(Recommended)*

```sql
SELECT player_id, event_date,
SUM(games_played) OVER (PARTITION BY player_id ORDER BY event_date) AS games_played_so_far
FROM Activity;
```

### 🛠️ How It Works

1. `PARTITION BY player_id` processes each player's records separately.
2. `ORDER BY event_date` arranges each player's logins chronologically.
3. `SUM(games_played) OVER (...)` computes the running total of games played up to the current date.
4. The result shows the cumulative games played for every login date.

---

### 💻 Approach 2: Self Join

```sql
SELECT a1.player_id, a1.event_date,
SUM(a2.games_played) AS games_played_so_far
FROM Activity a1
JOIN Activity a2 ON a1.player_id = a2.player_id AND a2.event_date <= a1.event_date
GROUP BY a1.player_id, a1.event_date;
```

### 🛠️ How It Works

1. Self join the table on the same `player_id`.
2. Match all previous (and current) dates using `a2.event_date <= a1.event_date`.
3. Sum the `games_played` values for those matching rows.
4. Group by player and date to get the cumulative games played.

---

### ⭐ Recommended Approach

The **Window Function (`SUM`)** approach is recommended because it computes the running total directly without requiring a self join, making it cleaner, faster, and easier to understand.

---

### ⏱️ Complexity Comparison

| Approach | Time Complexity | Space Complexity |
|----------|-----------------|------------------|
| Window Function (`SUM`) | `O(n log n)` | `O(n)` |
| Self Join | `O(n²)` | `O(n)` |
