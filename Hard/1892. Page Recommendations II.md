## 🚀 1892. Page Recommendations II 🔒

### 📖 Problem

You are implementing a page recommendation system for a social media website. Your system will **recommend** a page to `user_id` if the page is **liked** by **at least one** friend of `user_id` and is **not liked** by `user_id`.

Write a solution to find all the possible **page recommendations** for every user. Each recommendation should appear as a row in the result table with these columns:

- `user_id`: The ID of the user that your system is making the recommendation to.
- `page_id`: The ID of the page that will be recommended to `user_id`.
- `friends_likes`: The number of the friends of `user_id` that like `page_id`.

Return the result table in **any order**.

---

### 📝 Example

```text
Input: 
Likes table:             Friendship table:
+---------+---------+    +----------+----------+
| user_id | page_id |    | user1_id | user2_id |
+---------+---------+    +----------+----------+
| 1       | 88      |    | 1        | 2        |
| 2       | 23      |    | 1        | 3        |
| 3       | 24      |    | 1        | 4        |
| 4       | 56      |    | 2        | 3        |
| 5       | 11      |    | 2        | 4        |
| 6       | 33      |    | 2        | 5        |
| 2       | 77      |    | 6        | 1        |
| 3       | 77      |    +----------+----------+
| 6       | 88      |
+---------+---------+
Output: 
+---------+---------+---------------+
| user_id | page_id | friends_likes |
+---------+---------+---------------+
| 1       | 77      | 2             |
| 1       | 23      | 1             |
| 1       | 24      | 1             |
| 1       | 56      | 1             |
| 1       | 33      | 1             |
| 2       | 24      | 1             |
| 2       | 56      | 1             |
| 2       | 11      | 1             |
| 2       | 88      | 1             |
| 3       | 88      | 1             |
| 3       | 23      | 1             |
| 4       | 88      | 1             |
| 4       | 77      | 1             |
| 4       | 23      | 1             |
| 5       | 77      | 1             |
| 5       | 23      | 1             |
+---------+---------+---------------+
Explanation: 
Take user 1 as an example:
  - User 1 is friends with users 2, 3, 4, and 6.
  - Recommended pages are 23 (user 2 liked it), 24 (user 3 liked it), 56 (user 3 liked it), 33 (user 6 liked it), and 77 (user 2 and user 3 liked it).
  - Note that page 88 is not recommended because user 1 already liked it.

Another example is user 6:
  - User 6 is friends with user 1.
  - User 1 only liked page 88, but user 6 already liked it. Hence, user 6 has no recommendations.

You can recommend pages for users 2, 3, 4, and 5 using a similar process.
```
---

### 💡 Idea

First normalize the friendships so every friendship can be viewed from either user's perspective. Then find pages liked by their friends and exclude pages already liked by the user.

Finally, group by `user_id` and `page_id` to count how many friends liked each recommended page.

---

### 💻 Solution

```sql
WITH friends AS (
    SELECT user1_id AS user_id, user2_id AS friend_id FROM Friendship
    UNION ALL
    SELECT user2_id AS user_id, user1_id AS friend_id FROM Friendship
),
recommendations AS (
    SELECT f.user_id, l.page_id, COUNT(*) AS friends_likes
    FROM friends f
    JOIN Likes l ON f.friend_id = l.user_id
    LEFT JOIN Likes ul
        ON f.user_id = ul.user_id
        AND l.page_id = ul.page_id
    WHERE ul.page_id IS NULL
    GROUP BY f.user_id, l.page_id
)
SELECT user_id, page_id, friends_likes
FROM recommendations;
```

---

### 🛠️ How It Works

1. `friends` creates both directions for every friendship.
2. Join friends with `Likes` to find pages liked by each user's friends.
3. `LEFT JOIN` checks whether the user already likes the page.
4. `WHERE ul.page_id IS NULL` removes pages already liked by the user.
5. Group by user and page to combine duplicate recommendations.
6. `COUNT(*)` gives the number of friends who like each recommended page.

---

### ⏱️ Complexity

**Time Complexity:** `O(n × m)` *(processes friendships and their associated likes)*

**Space Complexity:** `O(n + m)` *(stores normalized friendships and recommendation results)*
