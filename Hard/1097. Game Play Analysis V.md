## 🚀 1097. Game Play Analysis V 🔒

### 📖 Problem

The **install date** of a player is the first login day of that player.

We define **day one retention** of some date `x` to be the number of players whose **install date** is `x` and they logged back in on the day right after `x`, divided by the number of players whose install date is `x`, rounded to `2` decimal places.

Write a solution to report for each install date, the number of players that installed the game on that day, and the day one retention.

Return the result table in **any order**.

---

### 📝 Example

```text
Input: 
Activity table:
+-----------+-----------+------------+--------------+
| player_id | device_id | event_date | games_played |
+-----------+-----------+------------+--------------+
| 1         | 2         | 2016-03-01 | 5            |
| 1         | 2         | 2016-03-02 | 6            |
| 2         | 3         | 2017-06-25 | 1            |
| 3         | 1         | 2016-03-01 | 0            |
| 3         | 4         | 2016-07-03 | 5            |
+-----------+-----------+------------+--------------+
Output: 
+------------+----------+----------------+
| install_dt | installs | Day1_retention |
+------------+----------+----------------+
| 2016-03-01 | 2        | 0.50           |
| 2017-06-25 | 1        | 0.00           |
+------------+----------+----------------+
Explanation: 
Player 1 and 3 installed the game on 2016-03-01 but only player 1 logged back in on 2016-03-02 so the day 1 retention of 2016-03-01 is 1 / 2 = 0.50
Player 2 installed the game on 2017-06-25 but didn't log back in on 2017-06-26 so the day 1 retention of 2017-06-25 is 0 / 1 = 0.00
```
---

### 💡 Idea

We need to find the **install date** for each player and then check whether they logged in again **the next day**.

First, find each player's first login date. Then join the `Activity` table again to check for a login exactly one day after the install date. Finally, group by install date and calculate the retention rate.

---

### 💻 Solution

```sql
WITH installs AS (
    SELECT player_id, MIN(event_date) AS install_dt
    FROM Activity
    GROUP BY player_id),
retention AS (
    SELECT i.player_id, i.install_dt,
    CASE WHEN a.event_date IS NOT NULL THEN 1
    ELSE 0 END AS retained
    FROM installs i
    LEFT JOIN Activity a ON i.player_id = a.player_id
        AND a.event_date = DATE_ADD(i.install_dt, INTERVAL 1 DAY))
SELECT install_dt,
COUNT(*) AS installs,
ROUND(AVG(retained), 2) AS Day1_retention
FROM retention
GROUP BY install_dt;
```
---

### 🛠️ How It Works

1. Find the earliest `event_date` for every player using `MIN()`.
2. Treat this earliest date as the player's `install_dt`.
3. Use `LEFT JOIN` to check whether the player logged in exactly one day later.
4. Mark players who returned the next day as `1`, otherwise `0`.
5. Group players by their install date.
6. Count the total installs for each date.
7. Use `AVG(retained)` to calculate the Day 1 retention rate.
8. Round the retention rate to 2 decimal places.

---

### ⏱️ Complexity

**Time Complexity:** `O(n)` *(scans the activity records for finding installs and checking next-day logins)*

**Space Complexity:** `O(n)` *(stores the intermediate install and retention results)*
