## 🚀 1917. Leetcodify Friends Recommendations 🔒

### 📖 Problem

Recommend friends to Leetcodify users. We recommend user `x` to user `y` if:

- Users `x` and `y` are not friends, and
- Users `x` and `y` listened to the same three or more different songs **on the same day**.

Note that friend recommendations are **unidirectional**, meaning if user `x` and user `y` should be recommended to each other, the result table should have both user `x` recommended to user `y` and user `y` recommended to user `x`. Also, note that the result table should not contain duplicates (i.e., user `y` should not be recommended to user `x` multiple times).

Return the result table in **any order**.

---

### 📝 Example

```text
Input: 
Listens table:                        Friendship table:
+---------+---------+------------+    +----------+----------+
| user_id | song_id | day        |    | user1_id | user2_id |
+---------+---------+------------+    +----------+----------+
| 1       | 10      | 2021-03-15 |    | 1        | 2        |
| 1       | 11      | 2021-03-15 |    +----------+----------+
| 1       | 12      | 2021-03-15 |
| 2       | 10      | 2021-03-15 |
| 2       | 11      | 2021-03-15 |
| 2       | 12      | 2021-03-15 |
| 3       | 10      | 2021-03-15 |
| 3       | 11      | 2021-03-15 |
| 3       | 12      | 2021-03-15 |
| 4       | 10      | 2021-03-15 |
| 4       | 11      | 2021-03-15 |
| 4       | 13      | 2021-03-15 |
| 5       | 10      | 2021-03-16 |
| 5       | 11      | 2021-03-16 |
| 5       | 12      | 2021-03-16 |
+---------+---------+------------+
Output: 
+---------+----------------+
| user_id | recommended_id |
+---------+----------------+
| 1       | 3              |
| 2       | 3              |
| 3       | 1              |
| 3       | 2              |
+---------+----------------+
Explanation: 
Users 1 and 2 listened to songs 10, 11, and 12 on the same day, but they are already friends.
Users 1 and 3 listened to songs 10, 11, and 12 on the same day. Since they are not friends, we recommend them to each other.
Users 1 and 4 did not listen to the same three songs.
Users 1 and 5 listened to songs 10, 11, and 12, but on different days.

Similarly, we can see that users 2 and 3 listened to songs 10, 11, and 12 on the same day and are not friends, so we recommend them to each other.
```
---

### 💡 Idea

* Self-join `Listens` to find pairs of users who listened to the **same songs on the same day**.
* Group by the two users and day, keeping pairs with at least **3 different songs**.
* Exclude users who are already friends.
* Since recommendations are unidirectional, generate both `(user1, user2)` and `(user2, user1)`.
* Use `DISTINCT` to avoid duplicate recommendations.

---

### 💻 Solution

```sql
WITH common_songs AS (
    SELECT l1.user_id AS user1, l2.user_id AS user2, l1.day
    FROM Listens l1
    JOIN Listens l2
        ON l1.song_id = l2.song_id
        AND l1.day = l2.day
        AND l1.user_id < l2.user_id
    GROUP BY l1.user_id, l2.user_id, l1.day
    HAVING COUNT(DISTINCT l1.song_id) >= 3
),
recommendations AS (
    SELECT user1 AS user_id, user2 AS recommended_id FROM common_songs
    UNION
    SELECT user2 AS user_id, user1 AS recommended_id FROM common_songs
)
SELECT DISTINCT r.user_id, r.recommended_id
FROM recommendations r
LEFT JOIN Friendship f
    ON (r.user_id = f.user1_id AND r.recommended_id = f.user2_id)
    OR (r.user_id = f.user2_id AND r.recommended_id = f.user1_id)
WHERE f.user1_id IS NULL;
```

---

### 🛠️ How It Works

1. Match listens from two different users when the **song and day are the same**.
2. `user1 < user2` ensures each user pair is considered only once.
3. Group by user pair and day and keep pairs sharing at least **3 different songs**.
4. Use `UNION` to create recommendations in both directions.
5. Check `Friendship` in either direction and remove existing friends.
6. `UNION` and `DISTINCT` ensure the final result contains no duplicates.

---

### ⏱️ Complexity

**Time Complexity:** `O(n²)` *(worst case, due to the self-join on `Listens`)*

**Space Complexity:** `O(n)` *(for the intermediate common-song and recommendation results)*
